# CLAUDE.md — SelfOrderResto (Hellom)

Aplikasi kasir (POS) + self-order restoran dan Landing Page Builder, bagian dari platform **Hellom** (hellomspace.com). Dijual sebagai SaaS multi-tenant: langganan bulanan/tahunan dan paket **lifetime** (bayar sekali, akses selamanya — tanpa license key/self-hosted).

Baca dulu: [README.md](README.md) (setup), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (tenant, role, realtime, billing), [docs/DEPLOY.md](docs/DEPLOY.md), [docs/AUDIT.md](docs/AUDIT.md) (temuan & status), [CHANGELOG.md](CHANGELOG.md).

## Layout
| Folder | Isi |
|---|---|
| `backend/` | Laravel 12 (PHP ^8.2, MySQL). API: `routes/api.php` → `routes/api/*.php` (prefix `/api/v1/hellom`). `routes/web.php` = `/media`, halaman toko Hellom Page (server-rendered) + fallback SPA. View: `resources/views/emails`, `resources/views/landing`. |
| `frontend/` | **UI satu-satunya**: React 19 + Vite 6 + TS + Tailwind 4, react-router 7. Build → `backend/public/hellom/` (git-ignored). Klien API: `src/services/api/*` (barrel `@/lib/hellomApi`). |
| `realtime/` | Socket.IO (`server.js`, :3001), PM2 `hellom-realtime`; token HMAC dari `GET /realtime/token`. |
| `deploy/` | `deploy.sh`, `ecosystem.config.js`, contoh Nginx, crontab. |
| `docs/` | ARCHITECTURE, DEPLOY, AUDIT, proposals/, notes/, design-reference/. |
| `_archive/` | Kode lama yang dipensiunkan (Blade UI, skrip debug, kelas tak terpakai) + README alasan. Jangan dipakai. |

## Perintah
```bash
# backend (butuh MySQL untuk migrate/tes; artisan lain jalan tanpa DB)
composer install
php artisan migrate                       # JANGAN migrate:fresh / db:wipe
php artisan route:list && php artisan config:cache && php artisan config:clear && php artisan route:cache && php artisan route:clear
php artisan serve --host=127.0.0.1 --port=8000
php artisan schedule:work                 # lokal; produksi: cron schedule:run

# frontend
npm install && npm run dev                # vite :3000
npx tsc --noEmit                          # harus 0 error (tsconfig strict: true)
npm run build                             # → ../backend/public/hellom

# realtime
node server.js                            # env: PORT, HOST, REALTIME_SERVER_SECRET, REALTIME_ALLOWED_ORIGINS, REALTIME_REQUIRE_AUTH
```
Tes PHPUnit fitur gagal di sqlite (migration memakai `information_schema` MySQL); tes unit jalan. Tes order/member POS: `php vendor/bin/phpunit -c phpunit.pos.xml` (MySQL `hellom_pos_test`, lihat [docs/ALUR_ORDER.md](docs/ALUR_ORDER.md) §10). Verifikasi backend dengan skrip `tinker` di `backend/storage/app/*.php` (git-ignored) dalam `DB::beginTransaction()/rollBack()`. **Hapus `bootstrap/cache/config.php` sebelum `php artisan test`.**

## Aturan domain yang wajib diingat
- **Isolasi tenant manual**: global scope `tenant` tidak aktif di API token. Setiap query POS filter `tenant_id` (`posTenantSlug` dari `InjectPosContext`, atau `OutletService::tenantSlugs($org)` untuk level organisasi). Endpoint publik mencari lewat token (`dining_tables.public_id`), bukan ID berurutan.
- **Akses berbayar** hanya lewat `App\Services\Billing\EntitlementService`; periode dari `Plan::accessEndsAt()`; cek akses dengan `Entitlement::allowsAccess()`.
- **Penarikan dana**: tinjauan/persetujuan hanya `super_admin`. **Setiap** penarikan menunggu persetujuan — juga di mode `auto` (transfer gateway hanya dimulai di `WithdrawalService::approve`, tidak pernah saat diajukan); pengajuan membuat notifikasi super admin (`NotificationService::createSellerWithdrawalNotif`).
- **Email**: semua email ke pengguna (verifikasi/login, reset password, penjualan, penarikan) lewat `PlatformMailService` = **email resmi** (SMTP + From di Super admin › Pengaturan Email). **Email owner** = `PlatformMailService::ownerEmails()` (SystemSetting `hellom_owner_notification_email`, kosong → email akun super_admin): setiap `OwnerNotification` disalin ke sana (`NotificationService::emailOwner`). Jangan hard-code alamat penerima admin.
- **Hak akses kasir POS**: katalog di `App\Support\Pos\PosPermissions` (`orders` selalu aktif; `manager` = owner/admin saja); setiap route POS wajib `->middleware('posPermission:<key>')`, cek di controller pakai `BasePosController::canPos()`. Tambah fitur POS baru → tambah key di katalog **dan** `FALLBACK_PERMISSIONS` (PosStaff.tsx) + `cashierNavigation` (PosLayout). Akses kasir terkini: `GET /pos/me/access`. Login kasir: `/login/kasir` → `POST /auth/staff-login` (`App\Services\Pos\StaffLogin`: pindah `current_organization_id` ke toko staf; tautan by email **hanya** untuk akun ber-email terverifikasi).
- Role: `users.role` (`super_admin`, `admin`, `tenant_admin`, `cashier`, `member`, `suspended`) + pivot `organization_user.role` (`owner`, `admin`, `member`, `cashier`). **`users.role = admin` = setiap pemilik yang daftar sendiri** — bukan admin platform: hanya boleh punya beberapa organisasi sendiri; akses ke organisasi **selalu** dari pivot (kecuali `super_admin`). Jangan pernah menambah cabang `role === 'admin'` yang membuka organisasi lain.
- **Super admin**: route di `routes/api/admin.php` (middleware `superAdmin`); setiap aksi tulis yang sensitif dicatat dengan `BaseApiController::adminAudit()` / `AuditLog::record` (organisasi = organisasi target; jangan simpan nilai rahasia). Hapus paket/user dijaga (arsip/suspend) karena FK cascade menghapus riwayat pembayaran. Tes: `tests/Admin` (`phpunit.pos.xml`), smoke browser `backend/tests/e2e/admin-smoke.mjs`; frontend `npm run lint:admin` harus 0 warning.
- **Pembayaran non-Hellom-Page** (langganan, produk digital, top-up, reconcile) via iPaymu: wajib `App\Services\Payments\IpaymuPaymentVerifier` (status + referensi + nominal + transaksi tidak dipakai ulang); notify URL iPaymu ditandatangani (`IpaymuPaymentVerifier::sign`). DOKU: HMAC + status API; status lunas tidak boleh turun. Tagih `intent.amount`, bukan `plan.price`.
- Error API (`api/*`) memakai amplop yang sama lewat renderer di `bootstrap/app.php`; 422 tetap punya `errors` per field.
- Respons API: `BaseApiController::ok()/fail()` (atau `success()/error()` di POS) — amplop `{ success, message, data, error }`.
- Validasi masih di controller (`$request->validate`) setelah cek otorisasi; kalau memakai Form Request, pindahkan otorisasi ke `authorize()` agar urutan 401/403 → 422 sama.
- Frontend: tipe respons API mengikuti payload backend; jangan menambah error `tsc`.

## Hellom Page (Landing Builder + toko online) — konteks proyek berjalan
Audit & status: [docs/AUDIT_LANDING_BUILDER.md](docs/AUDIT_LANDING_BUILDER.md). Dikerjakan per fase (1 audit → 2 uang → 3 produk → 4 builder/publik → 5 poles); **berhenti & minta konfirmasi setelah tiap fase**.
- Identitas penjual di modul ini = `organization_id` (halaman, blok, order, saldo, KYC) — dikonfirmasi pemilik (Q1).
- Keputusan pemilik (Q2–Q7): saldo **penjualan** terpisah dari saldo **top-up** (top-up tidak bisa ditarik); 1 halaman gratis per toko, halaman tambahan = langganan berbayar yang harganya diatur super admin (Fase 4); data produksi dipakai sungguhan (cek mock); gateway aktif = **iPaymu**; hotfix boleh; biaya gateway ditanggung Hellom dari biaya layanan: `platform_fee = max(harga×% + flat, biaya_gateway + margin_min)`.
- Uang: BIGINT rupiah; semua perubahan saldo dalam `DB::transaction(…, 3)` + `lockForUpdate`. Semua pembayaran pembeli masuk ke akun gateway Hellom; penjual punya **Saldo Penjualan** (`seller_balances` = cache, sumber kebenaran `seller_balance_ledger` append-only; `balance:reconcile`).
- **Checkout pembeli dibayar di halaman kita** (seperti produk Hellom sendiri, tanpa redirect ke iPaymu): `IpaymuGateway::paymentOptions()` = kanal direct yang aktif (`IpaymuSettingsService::enabledDirectChannels`: qris, bca, bni, …, indomaret, alfamart); `directCharge()` memakai payload & parsing yang sama dengan `ProductCheckoutService::createIpaymuDirectCharge` (kode QRIS sering di `PaymentNo`). QR digambar dari `qr_string` (frontend `OnPagePayment`, endpoint `/orders/{ref}/qr` = SVG). Instruksi tersimpan di `metadata.payment`, tampil lagi di `/pesanan/{ref}`. Diagnosa: `php artisan landing:payments-check`.
- Alur order: `LandingSaleService::createPendingOrder` → gateway lewat `App\Services\Payments\GatewayRegistry` (adapter `PaymentGateway`) → webhook/return/rekonsiliasi memanggil `SellerFinance\LandingPaymentService::handleNotification`, yang **selalu cek status + nominal ke API gateway** sebelum `settle()` (notifikasi iPaymu tidak bertanda tangan). Transisi status di `LandingPageOrder::TRANSITIONS`. Halaman `/pesanan/{ref}` hanya polling.
- Penarikan: `SellerFinance\WithdrawalService` (min/biaya/SLA/mode di `FinanceSettings`, SystemSetting `seller_finance_settings`); nama rekening harus sama dengan KYC; ganti rekening = tahan 24 jam + email. iPaymu tidak punya payout → mode manual (super admin transfer + unggah bukti di `/admin/keuangan-penjual`).
- Jadwal: `landing:orders reconcile|expire|release|sla`, `balance:reconcile` (routes/console.php). Tes: `tests/Landing` via `phpunit.pos.xml` (DB `hellom_pos_test`).
- Produk (Fase 3): `landing_products` (`public_id` di URL, `delivery_url`/`delivery_note` cast `encrypted`, file di disk `local`), dikelola `App\Services\Landing\ProductService`; checkout `CheckoutService` (reservasi stok/kupon, dilepas di `LandingPaymentService::moveFromPending`) + `PaymentStarter`; akses pembeli `OrderAccessService` (token = `landing_page_orders.download_token`); refund `RefundService` (ledger `refund`/`refund_reversal`, dibayar super admin). Blok produk menaut produk lewat `content.productId`; `publicPayload()` produk tidak boleh berisi data pengiriman. Endpoint penjual: `Concerns\ResolvesSellerOrganization` (owner/admin). URL publik baru: `/beli`, `/akses`, `/cek-pesanan`, `/kebijakan` → masuk daftar slug terlarang di Fase 4.
- Halaman (Fase 4): dokumen JSON per halaman — `organization_landing_pages.draft_document` (autosave, `draft_revision`) dan `landing_page_versions.document` (terbit, `published_version_id`); `App\Services\Landing\LandingDocumentService`, skema `App\Support\Landing\BlockSchema` (tambah field/tipe blok di sana **dan** di `frontend/.../landing-builder/types.ts` + `resources/views/landing/block.blade.php`). `landing_blocks` = format lama (hanya dibaca untuk konversi). Dokumen berversi (`schema_version`): ubah bentuk dokumen **hanya** lewat langkah baru di `App\Support\Landing\DocumentMigrator` (upgrade saat dibaca, jangan tulis ulang massal) + tes.
- Editor link-in-bio (sedang dikerjakan per fase, [docs/audit-linkinbio-builder.md](docs/audit-linkinbio-builder.md)): preset editor dari onboarding "Sebelumnya pakai apa?" (`users.builder_preference`, `landing-builder/presets.ts` + `editorPreference.tsx`, tur `EditorTour` via atribut `data-tour`). Banner video = link YouTube saja; font di-self-host. Editor (Fase 2): `Editor.tsx` + `editor/*` (`useEditorDocument` = state/undo/autosave); pratinjau HP = `POST …/site/pages/{id}/render` (Blade publik, `editor => true`, `views/landing/editor.js`) di iframe `sandbox="allow-scripts"` — jangan tambahkan `allow-same-origin`. Nama blok & galeri: `editor/blockMeta.ts`. Ongkir produk fisik (Fase 3): `App\Services\Shipping\*` (RajaOngkir; checkout **selalu** menghitung ulang tarif lewat `ShippingService::rateFor`, jangan pakai harga dari browser), asal pengiriman toko `organizations.landing_shipping`, mock e2e `RAJAONGKIR_SANDBOX_URL`. Biaya layanan dari harga produk saja (`FeeCalculator::split` param `feeBase`). Embed hanya lewat `App\Support\Landing\Embed` (domain = CSP `frame-src`). Sosial media (Fase 4) = `document.social`, link selalu dibangun server di `App\Support\Landing\SocialLinks` — ubah aturan di sana **dan** `editor/socialPlatforms.ts`, lalu jalankan `node tests/e2e/social-parity.mjs`. Tampilan (Fase 5, skema v3): `theme.bg` / `theme.button` / `headingFont`+`bodyFont` diolah `App\Support\Landing\ThemeStyle` (kontras teks otomatis, variabel CSS `--btn-*`, `buttonVars()` untuk gaya per tombol); tema siap pakai = `editor/themes.ts`. Font self-host: daftar di `App\Support\Landing\Fonts` **dan** `editor/fonts.ts`, file di `frontend/public/fonts/landing/` (`node scripts/fetch-landing-fonts.mjs`); pratinjau sandbox butuh header CORS pada font (Nginx `location ^~ /fonts/landing/`). Ikon tombol: `ButtonIcons` + `editor/buttonIcons.ts`. Statistik (Fase 6): link yang dilacak wajib punya `data-track` (page.blade menyisipkan `data-item` = id blok; sosial `social:<platform>`, WA mengambang `wa-float`), disimpan per `item` + `source` di `landing_stats_daily` (`LandingStats`). og:image otomatis = `App\Support\Landing\OgImage` lewat `/og/{username}/{slug|_}-{hash}` (hash dari isi terbit, file di disk `local`), `seo_image` penjual menang; jangan ambil gambar dari URL luar di sana. Fase 7: banner = field blok Profil (`coverVideo` hanya YouTube, diputar `script.js` setelah load); animasi = `theme.motion` (`ThemeStyle::motion`, pembungkus `.ent` di page.blade, hanya publik) + `styles.entrance` per blok; video lewat `Embed::resolve` + facade `views/landing/youtube.blade.php`; judul video = `GET …/video-preview` (`services.youtube.oembed_url`). **Template = data** di `backend/resources/landing/templates/*.json` (`TemplateLibrary`, slot gambar `{{slot:key}}` diisi super admin di Pengaturan › Template Halaman, SystemSetting `landing_templates`); template baru = file JSON baru yang lolos `LinkInBioExtrasTest` (AA 4.5:1). Pratinjau template dirender mode `sample` (seperti editor tanpa petunjuk/skrip editor).
- Halaman publik **dirender server**: `routes/web.php` `/{username}/{slug?}` → `LandingPublicController` (Blade `resources/views/landing/*`, cache per `LandingShop::bumpCache`); kata terlarang/unknown → `SpaController` (React). Konten penjual tetap data terstruktur; satu-satunya HTML mentah = blok `html` yang disanitasi. `PublicPage.tsx` React tinggal untuk dev/fallback. Username = `organizations.landing_username` ?? `slug` (slug tetap dipakai POS).
- Iklan: `LandingTrackingSetting` (ID divalidasi regex, token CAPI terenkripsi), `SendMetaPurchaseEvent`, event Purchase sekali via `purchase-event`; statistik `LandingStats` (`landing_stats_daily`, pakai 0 bukan NULL di kolom unik).
- Fase 5 (selesai; lanjutan pemilik 30 Sep selesai, menunggu konfirmasi): onboarding `GET /apps/landing-builder/onboarding` + `OnboardingWizard`/`OnboardingChecklist`; CSP halaman toko `App\Support\Landing\PageSecurity` (hash `script.js` — ubah script → hash ikut otomatis); middleware `shopManager` (owner/admin) untuk API builder lama; `GET /api/health` (`HealthController`, heartbeat scheduler); queue PM2 `hellom-queue`; `deploy/backup.sh`. E2E browser: `backend/tests/e2e/README.md` (iPaymu tiruan via `IPAYMU_SANDBOX_URL`, SMTP tiruan, DB `hellom_pos_test`, `CACHE_STORE=array`). Checklist HP: `docs/TESTING_HELLOM_PAGE.md`. Lanjutan (30 Sep): mode gelap dashboard = remap variabel warna Tailwind di `frontend/src/styles/dashboard-dark.css` (**hasil generate** `node scripts/gen-dark-theme.mjs`; `html.hl-dash`/`hl-dark` dipasang `useDashboardColorScheme` di `DashboardLayout`; bungkus pratinjau halaman penjual dengan `hl-light`); KTP & rekening = `PayoutAccountSheet` di tab Saldo; captcha `App\Services\Security\CheckoutCaptcha` (Turnstile, env `TURNSTILE_*`); `srcset` via `App\Support\ImageOptimizer` (+ `landing:image-variants`).
- Aturan brief: teks UI Bahasa Indonesia santai-profesional; FormData PUT/PATCH = POST + `_method`; boolean FormData pakai `filter_var(..., FILTER_VALIDATE_BOOLEAN)`; migration non-destruktif dengan `down()`; jangan `storage:link`; setelah perubahan instruksikan `php artisan optimize:clear`; jangan sentuh POS kecuali kode bersama (jelaskan dampak dulu).

## Aturan kerja
1. Jangan membaca, menampilkan, atau meng-commit `.env`, kredensial, API key, atau data pelanggan.
2. Jangan mengubah migration yang sudah dijalankan; buat migration baru. Jangan jalankan perintah penghapus data (`migrate:fresh`, `db:wipe`, `truncate`, `tenants:seed-demo --truncate`, `orders:purge-legacy --force`).
3. Sebelum menghapus file, buktikan tidak dipakai; kalau ragu pindahkan ke `_archive/` dan catat alasannya di `_archive/README.md`.
4. Setelah langkah besar: `composer install`, `route:list`, `config:cache`, `npm run build`, `npx tsc --noEmit`, tes. Perbaiki dulu kalau gagal.
5. Jangan menambah fitur atau mengubah logika bisnis/tampilan kecuali bug yang jelas — dan tanyakan dulu.
6. Keputusan ambigu → tanya pemilik proyek.
7. Commit kecil, conventional commits. **Stage file secara eksplisit** — pemilik sering punya perubahan belum di-commit (mis. `frontend/src/components/landing/HellomspaceLanding.tsx`); jangan `git add <folder>`.
8. Email saat verifikasi: tukar `PlatformMailService` dengan versi no-op di container; jangan pernah mengirim email sungguhan.
